Как это работает
На удалённом сервере администратор «публикует» одно или несколько приложений. Когда пользователь запускает ярлык этого приложения на своём компьютере, формируется RDP-сессия с сервером, запускается само приложение, и его окно отображается на локальном экране. Как настроить
Есть два основных подхода:
1. Через Remote Desktop Services (RDS) в Windows Server. Это официальный и полноценный способ. **Шаг 1 — Анализ инфраструктуры и выбор метода реализации**

**Объяснение/действие:**
Для реализации RemoteApp на Windows Server 2022 Standard нам необходимо выбрать один из двух путей, так как они кардинально отличаются по требованиям к инфраструктуре:

1. **Корпоративный путь (через роль RDS).** Развёртывание полноценной инфраструктуры Remote Desktop Services (Session Host, Connection Broker, Licensing). 
   *Факт:* Согласно официальной документации Microsoft, для стандартного развёртывания роли RDS и публикации RemoteApp **обязательно требуется наличие контроллера домена Active Directory (AD)**. На сервере в рабочей группе (Workgroup) установить роль RDCB (Connection Broker) стандартными средствами не получится.
2. **Упрощённый путь (через реестр и RDP-файлы).** Использование встроенных возможностей протокола RDP без установки роли RDS. Сервер настраивается через реестр (разрешение запуска удалённых приложений), а для клиентов генерируются специальные `.rdp` файлы (вручную или через утилиту *RemoteApp Tool*). 
   *Факт:* Этот метод не требует Active Directory, сервера лицензирования RDS и подходит для автономных серверов или небольших внедрений.

**Протокол (зафиксировано):**
*   **ОС:** Windows Server 2022 Standard.
*   **Целевое ПО:** Lvision.
*   **Цель:** Публикация окна Lvision на клиентских машинах без доступа к полному рабочему столу сервера.

**Шаг 2 — Анализ технических ограничений среды (лимит сессий и требование Active Directory)**

**Объяснение/действие:**
Поскольку выбран **упрощённый метод** (без установки полноценной роли Remote Desktop Services) и сервер находится в **рабочей группе (Workgroup)**, мы сталкиваемся с критическим ограничением операционной системы Windows Server 2022 Standard.

Согласно официальной документации Microsoft, без развёртывания роли RDS (Remote Desktop Services) на сервере доступны только **две (2) одновременные административные RDP-сессии**. Этот режим предназначен исключительно для удалённого управления сервером. 

Чтобы обеспечить одновременную работу **10 пользователей**, технически и лицензионно необходимо:
1. Установить роль RDS (включая компонент Session Host).
2. Развернуть Active Directory (AD DS), так как инфраструктура RDS требует наличия домена и официально не поддерживается в Workgroup.

Упрощённый метод (настройка через реестр и RDP-файлы без установки роли RDS) позволит запустить Lvision в режиме RemoteApp, но **строго для двух пользователей одновременно**. При попытке подключения большего числа пользователей новые сессии будут получать отказ или принудительно завершать работу уже подключённых.

**Протокол (обновлённый):**
*   **ОС:** Windows Server 2022 Standard.
*   **Среда:** Workgroup (Рабочая группа).
*   **Целевое ПО:** Lvision.
*   **Метод:** Упрощённый (настройка через реестр и RDP-файлы).
*   **Пользователи:** 10 (запланировано).
*   **Зафиксированное ограничение:** Без роли RDS и Active Directory технический лимит одновременных RDP-подключений в Windows Server 2022 равен 2.

**Вопросы:**
Как мы поступим с выявленным противоречием?
1. **Перейти к корпоративному методу:** развернуть на этом сервере Active Directory (сделать его контроллером домена) и установить полноценную роль RDS (потребуются лицензии RDS SAL на 10 пользователей).
2. **Остаться на упрощённом методе:** смириться с тем, что одновременно Lvision смогут использовать только 2 человека, а остальные 8 будут работать в другие смены или ждать очереди.
3. **Использовать неофициальные модификации:** применить патчи (например, RDP Wrapper Library или модификацию `termsrv.dll`), которые снимают лимит в 2 сессии в Workgroup. *Примечание: это нарушает лицензионное соглашение (EULA) Microsoft, не поддерживается официально и может сломаться после очередных обновлений безопасности Windows.*

**Шаг 3 — Оценка технических рисков и требований для обхода лимита сессий (RDP Wrapper)**

**Объяснение/действие:**
Вы выбрали метод обхода системных ограничений. Для снятия лимита в 2 одновременные RDP-сессии на Windows Server 2022 в рабочей группе используется библиотека **RDP Wrapper Library** (или её актуальные форки). 

Технически это работает следующим образом: системная служба `TermService` использует файл `termsrv.dll`. RDP Wrapper не модифицирует сам DLL-файл на диске (что снижает риск повреждения ОС), а внедряется в память процесса (inject) и перехватывает функции, отвечающие за проверку лимита сессий, подменяя их значениями из конфигурационного файла `rdpwrap.ini`.

**Критические факты и технические реалии для Windows Server 2022:**
1. **Оригинальный репозиторий заброшен.** Официальный репозиторий создателя (stascorp/rdpwrap) архивирован. Файл `rdpwrap.ini` из оригинального источника не содержит смещений (offsets) для актуальных сборок `termsrv.dll` Windows Server 2022 (Build 20348.xxxx). Для работы потребуется использовать поддерживаемые сообществом форки (например, от `sebaxakerhtc` или `affinityv`), которые регулярно парсят новые DLL и обновляют INI-файл.
2. **Конфликт с антивирусами.** Windows Defender и сторонние антивирусы часто классифицируют инжекты в системные процессы как `HackTool:Win32/RDPWrap` или `Trojan` и автоматически удаляют файлы. Потребуется добавление папки с инструментом в строгие исключения антивируса.
3. **Уязвимость к обновлениям Windows.** Любое ежемесячное обновление безопасности (Patch Tuesday), затрагивающее `termsrv.dll`, изменит его хеш и внутренние смещения. Это мгновенно сломает RDP Wrapper (статус сменится на `not listening` или `unsupported`), и пользователи потеряют доступ до тех пор, пока вы вручную не скачаете новый `rdpwrap.ini` и не перезапустите службу.
4. **Лицензионное соглашение.** Данный метод прямо нарушает условия лицензионного соглашения Microsoft (EULA).

**Протокол (обновлённый):**
*   **ОС:** Windows Server 2022 Standard.
*   **Среда:** Workgroup (Рабочая группа).
*   **Целевое ПО:** Lvision.
*   **Метод:** Упрощённый (реестр + RDP) + RDP Wrapper (обход лимита сессий).
*   **Пользователи:** 10 одновременных подключений.
*   **Статус:** Выбран неофициальный метод, требующий обхода защитных механизмов ОС и регулярного ручного обслуживания при обновлениях.

**Объяснение/действие:**
На скриншоте отображается критическая ошибка RemoteApp: 
`Windows не удается запустить данное удаленное приложение RemoteApp. Следующее удаленное приложение RemoteApp отсутствует в списке разрешенных программ: lvision`

Эта ошибка означает, что клиент успешно аутентифицировался (запрос пароля больше не появляется, Способ 1 с Диспетчером учётных данных сработал), но сервер **отказался запускать приложение**, так как не нашёл его в белом списке (`TSAppAllowList`).

**Причина ошибки:**
В Windows Server 2022 без роли RDS механизм `TSAppAllowList` работает особым образом. Если в реестре создан список разрешённых приложений, сервер начинает проверять **каждое** запрашиваемое приложение на соответствие этому списку. 
В вашем RDP-файле указан параметр `alternate shell:s:||C:\LVision\LVMain.exe` (или `remoteapplicationprogram`). Сервер извлекает из этого пути имя файла или алиас и сравнивает его с ключами в реестре. В ошибке явно указано, что он ищет программу с именем **`lvision`** (с маленькой буквы), но в реестре на Шаге 11 мы создали ключ с именем **`Lvision`** (с большой буквы) и привязали к нему путь. 

Кроме того, в упрощённом режиме (без RDS) часто возникает конфликт: если список `TSAppAllowList\Applications` не пуст, сервер требует точного совпадения алиаса. Но более надёжный метод для Workgroup — это разрешить запуск **любых** приложений, добавив специальный ключ-пустышку, либо исправить сопоставление.

Согласно документации Microsoft по настройке RemoteApp через реестр (TSAppAllowList), если вы хотите разрешить запуск конкретного приложения по полному пути, имя ключа в реестре должно строго соответствовать тому, что передаёт клиент, ИЛИ необходимо использовать специальный подход с разрешением всех приложений.

**Что нужно сделать на сервере (PowerShell от имени Администратора):**

Мы добавим в реестр разрешение на запуск любых приложений в режиме RemoteApp. Это стандартный обходной путь для упрощённого метода, когда нет Connection Broker. Для этого создаётся ключ с именем `*` (звёздочка) или параметр `fDisabledAllowList`.

Выполните команду:
```powershell
New-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Terminal Server\TSAppAllowList" -Name "fDisabledAllowList" -Value 1 -PropertyType DWord -Force
```

*Факт:* Параметр `fDisabledAllowList = 1` в ветке `TSAppAllowList` отключает проверку белого списка для RemoteApp в упрощённом режиме, разрешая запуск любого `.exe` файла, переданного в параметре `remoteapplicationprogram` или `alternate shell`. Это устраняет ошибку «отсутствует в списке разрешенных программ».

После выполнения команды **перезапустите службу TermService**, чтобы изменения вступили в силу:
```powershell
Restart-Service -Name TermService -Force
```
*(Примечание: перезапуск службы кратковременно разорвёт текущие RDP-сессии, но так как вы сейчас тестируете, это допустимо. Если вы подключены через консоль Hyper-V — вы не потеряете доступ).*

## Публикация приложения в режиме RemoteApp на Windows Server 2022 Standard (Workgroup) без роли RDS

### 0. Паспорт решения
*   **Сервер:** `wmsAPP`, Windows Server 2022 Standard, Build 20348.4294, IP `192.168.12.152`, рабочая группа (без Active Directory).
*   **Приложение:** Lvision, исполняемый файл `C:\LVision\LVMain.exe`.

### 2. Подготовка сервера (защитник Windows и папка инструментов)

При наличии стороннего антивируса — добавить `C:\RDPW` в его исключения.

### 3. Установка RDP Wrapper
1.  Скачать `RDPW_Installer.exe` из Releases (ссылка 1.2) и свежий `rdpwrap.ini` (ссылка 1.3), положить оба в `C:\RDPW`.
2.  Запустить `RDPW_Installer.exe` от имени Администратора.
3.  Проверить статус через `RDPConf.exe`: требуется `Wrapper state: Installed`, `Service state: Running`, `Listener state: Listening`, `[fully supported]`.
4.  Если служба остановлена — кнопка `Restart TermService` в `RDPConf.exe`, либо:

### 4. Включение удалённого доступа на сервере


### 5. Серверные параметры реестра для RemoteApp
```powershell
# 5.1 Регистрация приложения в списке TSAppAllowList
$appPath = "C:\LVision\LVMain.exe"
$regPath = "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Terminal Server\TSAppAllowList\Applications\Lvision"
New-Item -Path $regPath -Force
New-ItemProperty -Path $regPath -Name "Path" -Value $appPath -PropertyType String -Force
New-ItemProperty -Path $regPath -Name "ShowInWebAccess" -Value 1 -PropertyType DWord -Force

# 5.2 Отключение проверки белого списка
New-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Terminal Server\TSAppAllowList" -Name "fDisabledAllowList" -Value 1 -PropertyType DWord -Force

# 5.3 КЛЮЧЕВОЙ параметр запуска произвольных RemoteApp-программ (без него сервер создаёт сессию, но НЕ запускает процесс)
$key = "HKLM:\SOFTWARE\Policies\Microsoft\Windows NT\Terminal Services"
New-Item -Path $key -Force | Out-Null
New-ItemProperty -Path $key -Name "fAllowUnlistedRemotePrograms" -Value 1 -PropertyType DWord -Force
```
После пункта 5.3 **обязательна перезагрузка сервера** (перезапуска службы недостаточно):
```powershell
Restart-Computer -Force
```

### 8. Устранение неполадок (фактически встреченные ошибки и их причины)
| Симптом | Причина / решение |
|---|---|
| «Не включен удаленный доступ к серверу» | Не выполнен раздел 4; служба TermService остановлена (раздел 3, п.4). |
| Запрос пароля при запуске | Учётные данные не сохранены на клиенте (раздел 7.1). |
| «Укажите запускаемую удаленную программу...» | Префикс `\|\|` + алиас без серверных политик; привести файл к формату 7.2. |
| «...отсутствует в списке разрешенных программ: lvision» | Не применены `fDisabledAllowList` (5.2) и/или `fAllowUnlistedRemotePrograms` (5.3). |
| Зависание «Настройка удаленного сеанса...», окно не появляется | Сервер создал сессию, но не запустил процесс: отсутствует `fAllowUnlistedRemotePrograms` (проверяется: `query session` = Активно, `Get-Process` пуст). Решение — 5.3 + перезагрузка. |
| «Не удалось открыть программу или файл» | Старый формат файла (`\|\|` в `alternate shell`) либо права NTFS (раздел 6). |
| Event ID 8198 (Security-SPP) в журнале | Сбой автоактивации лицензии Windows; к запуску RemoteApp отношения **не имеет**. |
| RDPConf: `[not supported]` после обновлений Windows | Обновить `rdpwrap.ini` (кнопка `Update INI` или ссылка 1.3), затем `Restart TermService`. |

### 9. Диагностические команды (сервер)
```powershell

```
Сбор ошибок из журналов за последние 10 минут:
```powershell
$StartTime = (Get-Date).AddMinutes(-10)
$logs = @('Application','Microsoft-Windows-TerminalServices-RemoteConnectionManager/Operational','Microsoft-Windows-RemoteDesktopServices-RdpCoreTS/Operational')
foreach ($log in $logs) {
  Write-Output "===== $log ====="
  try {
    Get-WinEvent -FilterHashtable @{LogName=$log; Level=1,2,3; StartTime=$StartTime} -MaxEvents 30 -ErrorAction Stop |
    Where-Object { $_.Message -match 'LVMain|LVision|RemoteApp|TermService|RDP|удаленн|remote' -or $_.ProviderName -match 'Application Error|TermService|RemoteDesktopServices|RdpCoreTS|RemoteConnectionManager' } |
    Select-Object TimeCreated, Id, ProviderName, LevelDisplayName, Message | Format-List
  } catch { Write-Output "Журнал недоступен или нет подходящих записей: $($_.Exception.Message)" }
}
```
