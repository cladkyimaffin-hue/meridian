**Шаг 1.3 — Разъяснение требования "Прямой режим KeenDNS" для WireGuard**

**Объяснение:**  
Сообщение или требование о том, что для WireGuard нужен "Прямой режим KeenDNS", связано с тем, как работает доменная служба Keenetic.  
- **Прямой режим** означает, что ваш роутер получает от интернет-провайдера **публичный ("белый") IP-адрес**. В этом случае доменное имя (например, `myrouter.keenetic.pro`) напрямую указывает на этот IP, и UDP-трафик WireGuard (порт 51820) свободно доходит до роутера.  
- **Облачный режим** включается автоматически, если у вас нет публичного IP-адреса (роутер находится за NAT провайдера). В этом режиме KeenDNS работает как прокси, но **поддерживает только веб-трафик (HTTP/HTTPS)**. Он **не может** проксировать UDP-трафик, который необходим для работы WireGuard.  

Без публичного IP-адреса и прямого режима KeenDNS подключиться к WireGuard-серверу на роутере по доменному имени не получится.

**Шаг 2 — Анализ проблемы SSTP: конфликт IP-адресации**

Нашёл корневую проблему. Смотрю на ваши данные:

**Критическая проблема:**
- Пользователь `ant` имеет **постоянный IP: 192.168.12.204**
- Пул SSTP на роутере: **192.168.13.250/29** (диапазон 192.168.13.248-192.168.13.255)
- Клиент получил адрес: **192.168.12.204** (из локальной сети роутера, НЕ из пула VPN)

**Почему это ломает подключение:**
1. Адрес 192.168.12.204 находится в локальной сети роутера (192.168.12.0/24), а не в VPN-пуле (192.168.13.0/24)
2. Маска 255.255.255.255 означает, что клиент видит только свой адрес, но не может нормально маршрутизировать трафик
3. Нет шлюза по умолчанию для SSTP-подключения — весь трафик идет через локальную сеть, а не через VPN
4. Через несколько минут происходит конфликт или таймаут, и подключение разрывается

**Решение — два варианта:**

**Вариант А (рекомендую):** Изменить постоянный IP пользователя `ant` на адрес из пула SSTP
- На роутере Keenetic в настройках SSTP → Пользователи → `ant`
- Изменить "Постоянный IP-адрес" с `192.168.12.204` на `192.168.13.251` (или другой свободный из пула 192.168.13.248-255)
- Сохранить настройки

**Вариант Б:** Убрать постоянный IP у пользователя `ant`
- В настройках пользователя `ant` очистить поле "Постоянный IP-адрес" (оставить пустым)
- Клиент будет автоматически получать адрес из пула 192.168.13.250/29

**Как проверить результат после изменения:**
1. Переподключитесь к SSTP
2. Выполните `ipconfig /all` — адрес должен быть из диапазона 192.168.13.x
3. Выполните `ping 192.168.12.1` — должен проходить
4. Подключение должно оставаться стабильным

**Риск:** Низкий. Изменение настроек SSTP на роутере не влияет на текущие подключения других пользователей (если они есть).

**Шаг 7 — Диагностика черного экрана при RDP через VPN**

Черный экран с последующим разрывом сессии — типичный симптом проблемы с MTU или фрагментацией пакетов через VPN-туннель. RDP устанавливает соединение, начинает передавать данные, но пакеты не проходят корректно из-за размера.

**Назначение:** SSTP-сервер раздает клиентам адреса из пула 192.168.12.202-206 (5 адресов). NAT включен для доступа клиентов в интернет через роутер.

**⚠️ Критическая проблема:** Начальный IP-адрес 192.168.12.202 находится в той же подсети, что и Lan-12 (192.168.12.0/24). Это создает конфликт: VPN-клиенты получают адреса из локальной сети, а не из отдельной VPN-сети. Это может работать, но не рекомендуется.

## Действия с MTU

**Проблема:** Через VPN-туннель стандартный MTU 1500 слишком большой, пакеты фрагментируются или отбрасываются, что приводит к черному экрану при RDP.

**Выполненные действия:**
1. Проверили текущие MTU интерфейсов — VPN-интерфейс не отображался (не был подключен)
2. Проверили максимальный размер пакета пингом: `ping 192.168.12.201 -f -l 1300` — прошло успешно
3. Попытались установить MTU=1300 для интерфейса "Меридиан" — ошибка (интерфейс не найден)

**Правильный способ установить MTU:**
1. Подключить VPN "Меридиан"
2. Выполнить `netsh interface ipv4 show subinterfaces` — найти точное имя VPN-интерфейса (обычно "WAN Miniport (SSTP)" или номер интерфейса)
3. Выполнить команду с правильным именем:
   ```cmd
   netsh interface ipv4 set subinterface "WAN Miniport (SSTP)" mtu=1300 store=persistent
   ```
   Или по номеру интерфейса (например, если номер 15):
   ```cmd
   netsh interface ipv4 set subinterface 15 mtu=1300 store=persistent
   ```
