# 📁 Индекс папки: WmsHost

**Описание:** База знаний по развертыванию, диагностике, обслуживанию и оптимизации хост-серверов WmsHost (гипервизор Hyper-V, Windows Server) и гостевых операционных систем (Ubuntu).

## 📄 Список файлов и их назначение

1. [Клонирование ВМ.md](./%D0%9A%D0%BB%D0%BE%D0%BD%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5%20%D0%92%D0%9C.md)
   - **Краткое содержание:** Пошаговая инструкция по клонированию виртуальной машины (из `wmsWiFi` в `wmsSQL-Analytics`) на гипервизоре Hyper-V.
   - **Ключевые этапы:** 
     - Копирование диска и создание новой конфигурации ВМ.
     - Устранение ошибки Secure Boot при первом запуске.
     - Смена hostname на `wmssql-analytics` через утилиту `hostnamectl`.
     - Настройка постоянного статического IP-адреса (`192.168.12.202`) через редактирование конфигурации Netplan (`/etc/netplan/50-cloud-init.yaml`).

2. [Утечка памяти.md](./%D0%A3%D1%82%D0%B5%D1%87%D0%BA%D0%B0%20%D0%BF%D0%B0%D0%BC%D1%8F%D1%82%D0%B8.md)
   - **Краткое содержание:** Расследование инцидента с критической загрузкой памяти (>90%) на хосте Hyper-V, зафиксированного в Zabbix.
   - **Ключевые этапы:** 
     - Анализ аномальных процессов (например, `ppbd.exe`).
     - Выявление корневой причины: суммарное статическое выделение RAM виртуальным машинам превысило физический объем памяти хоста.
     - Экстренное устранение: остановка новой ВМ `wmsDB_TEST` (8 ГБ), что мгновенно снизило нагрузку.
     - Долгосрочное решение: переход на Dynamic Memory и аудит лимитов выделения ресурсов.
