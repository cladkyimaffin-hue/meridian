# Медленная сеть wmssql-analytics через шлюз 192.168.12.176

Источник: сырой чат `Chats/Подключение серверов к cloude Prometheus и Grafana.md`. Пометки: VERIFIED — проверено в чате; ADMIN — со слов администратора; INFERRED — вывод.

## 1. Симптомы

- Скачивание с зеркала Ubuntu шло около 2–6 КБ/с (VERIFIED); индекс пакетов 1,4 МБ качался несколько минут.
- Репозиторий Docker (`download.docker.com`) в большинстве попыток не отдавал данные (VERIFIED); установка Docker не завершилась.
- Пинги нормальные (около 40 мс), небольшие запросы проходили (VERIFIED).

## 2. Отвергнутые гипотезы

- Шейпинг или перегрузка на самой машине → отвергнута: трафик на eth0 почти нулевой, повторных передач около 0,5% (VERIFIED).
- IPv6 → не работает совсем; apt принуждён к IPv4, на скорость это не повлияло (VERIFIED).
- MTU → пакеты размером 1452 терялись, 1400 проходили; временная установка MTU 1400 дала слабое улучшение, возвращено 1500 (VERIFIED).
- Проблема общая для всех ВМ → отвергнута: `wmsDB-TEST` ходит через шлюз 192.168.12.1 и качал с того же зеркала около 690 КБ/с (VERIFIED).

## 3. Диагностика

- Шлюз по умолчанию задан статически в netplan: 192.168.12.176. Путь идёт через 192.168.215.2 (задержки 21–67 мс с большим разбросом) и затем через адрес 100.68.0.1 из диапазона CGNAT (VERIFIED).
- Временные маршруты к зеркалу Ubuntu и к `download.docker.com` через 192.168.12.1 дали около 761 КБ/с против 2,4 КБ/с через .176; маршруты сразу удалены (VERIFIED). Дословные команды в чате не приведены.
- `loca.lt` и `registry-1.docker.io` доступны через оба шлюза; Telegram недоступен через оба (VERIFIED).

## 4. Корневая причина

На пути через 192.168.12.176 ограничена пропускная способность (INFERRED: вывод из измерений). Администратор увеличил скорость роутера, после чего установка прошла нормально (ADMIN, VERIFIED повторной установкой). Что именно было ограничено на роутере или у провайдера, неизвестно (UNKNOWN). Зачем на сервере статически задан шлюз .176, из материалов не видно (UNKNOWN).

## 5. Решение

1. Администратор увеличил скорость роутера (решающее действие).
2. Проверка через .176 после этого: Docker 29.9.3 и Compose v5.7.0 установились, `hello-world` скачался.
3. Запасные варианты, не понадобившиеся: временная смена маршрута по умолчанию на 192.168.12.1 до перезагрузки; постоянная смена шлюза в netplan (нужна оговорка, не зависят ли от .176 VPN, туннель или обход блокировок); офлайн-установка из общей папки.

## 6. ⛔ Don't repeat

- Не запускать установку Docker и скачивание образов при скорости загрузки в единицы КБ/с.
- Не менять MTU на постоянной основе.
- Не считать, что IPv6 может помочь: он не маршрутизируется.
- Учитывать, что исходящий трафик сервисов на машине идёт через выбранный шлюз; при смене шлюза проверять `ai-grafana-analyst`, `n8n` и туннель `loca.lt`.

## 7. Проверка результата

- [x] Docker установлен и работает (`docker run hello-world`), скачаны образы Prometheus и Grafana.
- [ ] Скорость через .176 стабильна: после установки не измерялась, перепроверить при следующей проблеме с загрузками.
