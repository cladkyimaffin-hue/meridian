# Исходные документы: интеграция 1С:ERP ↔ WMS LVision и спецификация требований

Раздел хранит **текстовые версии** исходных документов, полученных от заказчика и подрядчика (ООО «Кодерлайн проекты», ООО «АНТ Технолоджис»). Оригиналы (PDF/DOCX) в публичный репозиторий не кладутся — они лежат вне git (см. «Где оригиналы»).

Документы нужны для двух вещей: (1) понимать, откуда в базу `LV_MERIDIAN` приходят данные и что означает каждый тип прихода/расхода; (2) строить отчёты и сверки так, как это описано в требованиях, а не по догадкам.

## Как это связано с базой

| Документ | Что даёт для отчётов и карты данных |
|---|---|
| 04 (список документов) | Расшифровка кодов `1..7` в типах прихода и расхода — без него статусы в отчётах бессмысленны |
| 02, 03 | Какие поля 1С пишет в «Базу SQL», в каком порядке меняются статусы (ожидание → приёмка → факт), что считается расхождением |
| 01 | Структура справочников и настроек обмена: какие таблицы заполняются из 1С, а какие ведутся в WMS |
| 05 | Эталон бизнес-процесса: какие зоны и типы ячеек должны быть, как считается размещение и резервирование — по нему проверяются отчёты «Остатки», «Движение», «Задачи» |

Связь с таблицами `LV_MERIDIAN` описана в [карте данных](../DATA-MAP-LV_MERIDIAN.md): `LV_Receipt`/`LV_ReceiptItem`, `LV_Order`/`LV_OrderItem`/`LV_OrderShipment`, `LV_ImpLog*` (журнал импорта из 1С), `ANT_Export*` (выгрузка обратно).

## Ограничения текстовых версий

- Таблицы DOCX перенесены как markdown-таблицы; объединённые ячейки разворачиваются повтором значения — визуально это заметно, смысл сохраняется.
- В PDF-версии спецификации потеряны колонтитулы, номера страниц и часть оформления; **номера страниц сохранены комментариями** `<!-- page N -->`, по ним можно сверяться с оригиналом.
- Картинки и схемы не извлекались: в спецификации они есть (схема склада, примеры экранов). Смотреть в оригинале.
- При расхождении текста с оригиналом прав оригинал.
