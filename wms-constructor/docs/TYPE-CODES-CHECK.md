## 4. Что требует решения (не ошибки сверки, а вопросы к процессу)

### 4.1 Приходы без типа: 30 документов (10 %)

Все созданы в узком окне — апрель (6) и май (24) 2026. Коды документов вида `ER041`,
`ER044`… — то есть пришли из 1С по старой схеме, до того как в обмен добавили
`rct_TypeID`. В отчётах они попадают в строку «-».

Что делать: либо оставить как «тип не указан» (честно), либо запросить у 1С
дозаполнение исторических документов. Решение за заказчиком — менять данные
в боевой базе мы не будем.

### 4.2 Тип прихода 2 «Давальческое производство» — в ТЗ «НЕТ»

В таблице [04-Список-документов-выгрузки-1С.md](integration-1c/04-Список-документов-выгрузки-1С.md)
по типу 2 стоит «Принято: **НЕТ**», то есть функционал определения этого типа
в 1С ещё не согласован. При этом в базе уже **42 документа** с этим типом
(и они идут с декабря 2025 по сентябрь 2026). Значит либо 1С уже выставляет тип 2
по своей логике, либо его ставят вручную.

Это единственное настоящее расхождение между ТЗ и фактом, и оно не про коды,
а про готовность интеграции. Стоит уточнить у подрядчика, чем сейчас
определяется тип 2.

### 4.3 Тип расхода 2 «Перемещение»: в ТЗ два условия

В ТЗ: «Перемещение товаров **или** отсутствие распоряжения». То есть код 2 может
означать и настоящий документ перемещения, и документ без документа-основания.
Различить их по `ord_TypeID` нельзя — нужен признак наличия распоряжения, а его
в `LV_Order` нет отдельным полем. Для отчётов это значит: тип 2 нельзя трактовать
как «внутрискладское перемещение» без оговорки.

## 5. Практические выводы для отчётов

1. Названия типов брать из справочников (`LV_ReceiptType.rtt_Description`,
   `LV_OrderType.ort_Description`), а не хардкодить по коду — но всегда через
   `LTRIM(RTRIM(...))` и `ISNULL(..., '-')`.
2. Статусы выводить через `LV_Messages.msg_Greek` при `msg_languageID=4`
   (шаблон уже используется в витринах `dm_receipts` / `dm_orders`).
3. «Тип не указан» — законная категория, не прятать её из отчётов: иначе сумма
   по типам не сойдётся с общим числом документов (298 против 268).
4. Количества между единицами измерения не суммировать — см.
   [DATA-MAP-LV_MERIDIAN.md](DATA-MAP-LV_MERIDIAN.md), раздел 9.
