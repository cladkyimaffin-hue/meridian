# Контекст для нового чата (ИИ-помощника): конструктор запросов LV_MERIDIAN

Прочитайте целиком, затем `README.md`, `docs/DECISIONS.md`, `docs/ROADMAP.md`. Метки достоверности:
VERIFIED (подтверждено данными или командой), INFERRED (вывод по косвенным признакам), UNKNOWN (неизвестно).

## Правила работы с пользователем (его сохранённые предпочтения)
* Язык общения русский; небольшие шаги; явная уверенность по выводам (VERIFIED/INFERRED/UNKNOWN).
* Ничего «втихую»: каждое изменение называть; перед необратимыми действиями подтверждение.
* В конце ответа: что сделано, что проверено, что не проверено, что требует решения.
* Без выдуманных данных (пароли, IP, ID). Секреты только в непубличных файлах вне репозитория.
* Команды выписывать в файл команд с классификацией [R]/[W]/[D] (`docs/COMMANDS.md`).
* Сырые чаты не удалять: обрабатывать и помещать в репозиторий (`Chats/`), предварительно убрав секреты и личные данные.

## Что это и где живёт
* Приложение: `/opt/meridian/wms-constructor` на сервере `wmssql-analytics` (VERIFIED), контейнер `wms-constructor`, порт 8080 на адресе локальной сети.
* БД: MS SQL, базы `LV_MERIDIAN` (WMS) и `MRDN_Exchange` (обмен с 1С). Учётная запись `constructor_ro`: только чтение (VERIFIED).
* Grafana 12.2.0 на том же сервере; 14 дашбордов «Отчёты WMS» — источник запросов (`/opt/monitoring/work/sql_queries_dashboards_2026-11-20.md`).
* Репозиторий GitHub `cladkyimaffin-hue/meridian` (папка `wms-constructor`), публичный (по решению пользователя). Вход на сервер по SSH-ключу, deploy key с правом записи.

## Состояние на 2026-11-22
* Готово (VERIFIED): 101 запрос в `queries/*.yaml`, интерфейс с вкладками, Excel, 27 тестов зелёные, проверка на реальной БД (сводки, обменная база, запросы с датами).
* Нет авторизации: решение пользователя «доверяю всем в сети», доступ только из локальной сети, наружу не выставлять.
* Caddy: контейнеры `portal-caddy` (статический портал, порт 80, HTTP, `admin off`) и `vaultwarden-caddy` (менеджер паролей, не трогать). Конструктор пока работает напрямую на порту 8080, подключение к Caddy не делалось (решения нет).
* Файрвол `ufw` включён; порт 8080 в правилах не указан (Docker обходит ufw; доступ с ПК пользователя подтверждён им).

## Ограничения данных (из предыдущих чатов)
* Макросы Grafana заменены параметрами; количества нельзя суммировать между единицами измерения (штука, пара, метр, комплект).
* Русские подписи статусов и типов операций: `LV_Messages` (язык 4, поле `msg_Greek`) и `LV_UnitLang` (язык 4).
* Значения КМ, номера коробов, SSCC в отчёты не выводятся. Пароли, документы, адреса, контакты, оклады и ставки сотрудников не выводить.
* Открытые вопросы по данным WMS (к разработчику WMS): смысл статусов выгрузки 99/109/199/299, заказы без кода клиента, пустые коды заголовков заказов, кириллическая «М» в 4 кодах приходов, КМ без статуса, расхождения флага и `LV_CountStockDif`, тестовый товар `PRDTEST004`, 11 товаров с суммой журнала не равной остатку.

## Metabase (пробная установка, 2026-11-23)
* Папка `metabase/`: `docker-compose.yml` (Metabase v0.65.4.x и PostgreSQL 17, контейнеры `metabase` и `metabase-db`), порт 3001 в локальной сети. Секреты: `/opt/wms-constructor-secrets/metabase.env` (вне репозитория).
* Образ Metabase перенесён с сервера wmswifi (рабочая платформа Wi-Fi, не трогать его контейнеры): Docker Hub с wmssql-analytics грузился слишком медленно.
* Первичная настройка (учётная запись администратора, подключение SQL Server под `constructor_ro`) делается пользователем в браузере. Для работы через API нужен API-ключ, который пользователь кладёт в файл секретов; ключ использовать только внутри команд, значение не выводить.
* Ограничения Metabase (по документации): нет соединений между разными базами (обменная база `MRDN_Exchange` доступна только через SQL по полному имени `MRDN_Exchange.dbo.<таблица>` в одном подключении), отчёты хранятся в PostgreSQL, а не в git (нужны резервные копии).
* Цель пробы: проверить, подходит ли Metabase для идеи конструктора-«пазла» на 5 темах (остатки, приходы, задачи, движение, обмен с 1С).
