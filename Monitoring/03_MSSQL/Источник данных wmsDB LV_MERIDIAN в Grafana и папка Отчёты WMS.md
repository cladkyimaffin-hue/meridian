# Источник данных wmsDB LV_MERIDIAN в Grafana и папка Отчёты WMS

## Что настраивается и зачем

Подготовка к запуску обмена с 1С ERP: Grafana читает базу WMS, чтобы по её таблицам строить складские отчёты. Решения администратора 2026-11-17: работать с боевой `wmsDB` (не с `wmsDB-TEST`); читающий SQL-логин уже создан для чтения таблиц (имя и пароль — только в приватном `meridian-secrets`, см. `MONITORING-PROMETHEUS-GRAFANA-SETUP-2026-001` и файл фактов); порядок — сначала исследуем таблицы и возможные отчёты, потом делаем дашборды. Цель: подготовиться к запуску базы, наладить отчёты и разобраться в таблицах и их связях.

## Состояние базы (VERIFIED, 2026-11-17, только чтение)

- Сервер `wmsDB` (192.168.12.153): SQL Server 2019 (RTM). В исходном документе проекта была версия 2017: устарела.
- База `LV_MERIDIAN`: 1238 таблиц. База `MRDN_Exchange`: 30 таблиц с префиксом `IFC_` («интерфейс»), 31 процедура, представлений нет, внешних ключей нет вообще. Назначение `MRDN_Exchange`: слой обмена между WMS и внешней системой, то есть будущей 1С ERP (INFERRED по составу). Таблицы по отчётам — в отдельном документе домена.
- База боевая, но вводится в эксплуатацию: недавно прошло более 500 тестов, сейчас база ждёт внедрения 1С ERP, поэтому затишье (ADMIN, 2026-11-17). По данным последняя операция журнала от 2026-11-05, последнее выполненное задание от 2026-10-28 (VERIFIED), «горячих» таблиц сейчас, скорее всего, нет (INFERRED).

## Права читающего логина

- В `LV_MERIDIAN`: роль `db_datareader` и `VIEW DEFINITION` (выданы ранее администратором). Вход с `wmssql-analytics` через `sqlcmd` работает, чтение проверено (VERIFIED 2026-11-17). Право `VIEW DATABASE STATE` не выдано.
- В `MRDN_Exchange`: доступа не было. Администратор поручил «дать всё необходимое»; сведено к минимуму (чтение данных и схемы), скрипт подготовил Claude, выполнил администратор под учётной записью с правами `sysadmin` (2026-11-17) [W]; вместо `<читающий_логин>` подставляется имя из приватного реестра:

  ```sql
  USE MRDN_Exchange;
  CREATE USER <читающий_логин> FOR LOGIN <читающий_логин>;
  ALTER ROLE db_datareader ADD MEMBER <читающий_логин>;
  GRANT VIEW DEFINITION TO <читающий_логин>;
  ```

  Вход в `MRDN_Exchange` и членство в `db_datareader` проверены (VERIFIED). Откат: `DROP USER <читающий_логин>` в этой базе (под `sysadmin`, [D]).

## Шаги на `wmssql-analytics` [W]

Перед каждой правкой сделана копия `*.bak-ДАТА`. Выполнялось после согласия администратора.

**2026-11-17 — источник данных:**
1. `/opt/monitoring/docker-compose.yml`: в блок `grafana` добавлена одна строка `SQL_RO_PASSWORD: ${SQL_RO_PASSWORD}` (копия `docker-compose.yml.bak-2026-11-17`).
2. `/opt/monitoring/.env` (права 600): добавлена переменная `SQL_RO_PASSWORD` со значением из закрытого файла `/opt/monitoring/secrets/` (копия `.env.bak-2026-11-17`, права 600); значение не показывалось.
3. Новый файл `grafana/provisioning/datasources/wmsdb-lv-meridian.yml`: источник Microsoft SQL Server «wmsDB LV_MERIDIAN (read-only)», неизменяемый, пароль из переменной окружения, сам пароль в файле не хранится.
4. Контейнер `grafana` пересоздан: `docker compose up -d grafana`. Простой около 4 секунд (публичные дашборды мониторинга на это время недоступны); данные и настройки в томе сохранились.

**2026-11-18 — папка «Отчёты WMS»:**
5. Каталог `/opt/monitoring/grafana/dashboards-reports/` для складских отчётов.
6. `docker-compose.yml`: добавлено монтирование этого каталога в Grafana только для чтения (копия `docker-compose.yml.bak-2026-11-18`).
7. `grafana/provisioning/dashboards/dashboards.yml`: второй источник дашбордов «reports» с папкой Grafana «Отчёты WMS» (копия `dashboards.yml.bak-2026-11-18`).
8. Контейнер `grafana` пересоздан ещё раз (простой несколько секунд). Название папки выбрал Claude, администратор утвердил («папка подойдёт»). Папка «Monitoring» осталась только для мониторинга серверов.

Дашборды в папке — в отдельном документе каталога `04_Dashboards` (создаётся следующим шагом работ).

## Решения и риски

- Пароль читающего логина теперь в трёх местах: закрытый файл `secrets/`, `.env` (600) и среда контейнера Grafana (видна в `docker inspect`); место нужно внести в реестр секретов `meridian-secrets` (внесено в отдельном шаге работ).
- Доступ к источнику — вся база `LV_MERIDIAN` для чтения, соблюдать правило: новые складские дашборды не публикуются по ссылкам.
