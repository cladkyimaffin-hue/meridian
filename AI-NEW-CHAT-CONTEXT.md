# AI-NEW-CHAT-CONTEXT.md — контекст для новых чатов по внесению данных в meridian

Этот файл читается первым в любом новом чате, который вносит данные в `cladkyimaffin-hue/meridian`. Он задаёт порядок работы и формат результата. При противоречии с `AI-INSTRUCTIONS.md` или протоколом домена приоритет у них.

---

## 1. Репозиторий

- GitHub: `cladkyimaffin-hue/meridian`, ветка `main`. Репозиторий **публичный**; секреты в нём недопустимы (`AI-ADD-DATA-Cloud-INSTRUCTIONS.md`, раздел 7а). Решение, оставлять ли репозиторий публичным, не принято: пока считать его публичным.
- Метаданные документов определяет корневой `SCHEMA.md`. У каждого домена в конвейере свой набор служебных файлов в `<домен>/00_Meta/`: `SCHEMA.md` (доменные дополнения), `TAGS.md`, `registry.csv`, `CHANGELOG.md`, `CONFLICTS.md`, `TEMPLATES/`.
- Корень домена содержит `START-HERE.md`, `AI-README.md`, `INDEX.md`, `AI-environment_facts-meridian-<домен>.md`.
- Домены и их состояние — в `AI-INSTRUCTIONS.md`, раздел 7. В конвейере сейчас только `Monitoring/`. Папки `wmsBD/`, `WmsHost/`, `RemoteAPP/`, `wmsWIFI/` содержат сырые чаты и свои старые `INDEX.md`; они переводятся в конвейер по одной, отдельным шагом.
- В корне лежит необработанный файл «chat--Настройка SSTP vpn меридиан и подключение к 12 сети.txt»; домен для него не выбран.
- Имена папок проверяй по листингу каталога, а не по памяти.

## 2. Порядок чтения перед любым изменением

1. `AI-INSTRUCTIONS.md`.
2. `AI-ADD-DATA-Cloud-INSTRUCTIONS.md`.
3. Корневой `SCHEMA.md` и служебные файлы домена: `START-HERE.md`, `AI-README.md`, `00_Meta/SCHEMA.md`, `TAGS.md`, `registry.csv`, `INDEX.md`, `AI-environment_facts-*.md`, `CONFLICTS.md`, `CHANGELOG.md`.
4. 2–3 похожих документа домена, если они есть.

**Перед правкой файла перечитай его актуальное состояние из `main`:** параллельные сессии и администратор могут менять файлы.

---

## 3. Правило полного файла

Изменённый файл отдаётся и записывается **целиком**, с путём от корня. Фрагменты и «вставь после строки N» не используются. Исключение: строка в конец `CHANGELOG.md` или `registry.csv`. Неизменённые файлы не трогаются.

---

## 4. Запись в репозиторий

- Каждое изменение делается в отдельной ветке от актуального `main`; в `main` напрямую не писать.
- Pull request создаёт и сливает пользователь. Вместо формы PR дай ссылку `https://github.com/cladkyimaffin-hue/meridian/compare/main...<ветка>`, заголовок и описание PR в блоках кода. После слияния проверь, что PR действительно слит.
- Запись идёт полной перезаписью (`create_or_update_file` с `sha` или `push_files`). После каждого коммита сверь статистику изменений с задуманным через `get_commit`: любое лишнее изменение — ошибка.
- Коммиты в стиле `docs(область): суть`, в теле — источник.
- Если запись недоступна (`403`), отдай файлы для ручной замены и **не пиши «записано»**.
- Перед записью покажи план: какие файлы меняются, зачем, что проверено.
- Если `main` изменился с момента чтения, собери версию поверх актуальной, а не поверх своей копии.

## 5. Проверки перед выдачей

- Фронтматтер проходит YAML-парсер; строки с `:`, `#`, `[`, `]`, `{`, `}`, `|`, `>` в двойных кавычках.
- Блоки кода открыты и закрыты, у каждого указан язык.
- Таблицы в синтаксисе с `|`, после каждой пустая строка.
- Теги есть в `TAGS.md`, не дублируются, не стоят в двух группах.
- `document_id` уникален и есть в `registry.csv`; `registry.title` == `frontmatter.title` == H1; `registry.category` == `frontmatter.category` == папка из `registry.file_path`.
- Ссылки в `INDEX.md` и `related_files` ведут на существующие файлы; русские пути кодируются.
- `CHANGELOG.md`: строка `ГГГГ-ММ-ДД | тип | что сделано | кем`.
- Противоречие между источниками — запись в `CONFLICTS.md`, а не тихая правка.
- **Секреты:** в файлах нет паролей, токенов, ключей, лицензионных ключей и учётных данных.

Минимальный автоматический аудит (запускать из папки домена, например `Monitoring/`):

```python
import csv, re, os, glob, yaml
rows = list(csv.DictReader(open("00_Meta/registry.csv", encoding="utf-8")))
ids = [r["document_id"] for r in rows]
print("дубли ID:", {i for i in ids if ids.count(i) > 1} or "нет")
for r in rows:
    if not os.path.exists(r["file_path"]):
        print("нет файла:", r["document_id"], r["file_path"])
for f in glob.glob("**/*.md", recursive=True):
    t = open(f, encoding="utf-8").read()
    if t.count("```") % 2:
        print("незакрытый блок кода:", f)
    m = re.match(r"---\n(.*?)\n---\n", t, re.S)
    if m:
        try:
            yaml.safe_load(m.group(1))
        except Exception as e:
            print("YAML:", f, str(e).splitlines()[0])
```

Скрипт не заменяет проверку человеком.

## 7. Типичные ошибки (перенесены из korona)

- Фронтматтер без кавычек в строках с `:` — YAML не парсится.
- Блоки кода с потерянными маркерами — остальной текст рендерится как код.
- Таблицы с табуляцией вместо `|`.
- `INDEX.md`, оборванный посреди блока кода.
- Категория-подпапка без описания в `AI-README.md`.
- Копия служебного файла в `99_Archive/`.
- `title` в registry и во фронтматтере расходятся.
- Файлы-заглушки со случайными именами вместо `.gitkeep`.
- «Вставь после строки N» вместо полного файла.

## 8. Формат ответа пользователю

- Русский язык.
- Маленькие шаги, явная уверенность по выводам: VERIFIED, INFERRED, UNKNOWN.
- Без изменений «втихую»: каждое изменение названо и объяснено.
- Лог того, что сделано и что показало.
- Нейтральный, фактический язык: проблемы описываются как задачи.
- Неподтверждённое — `NEEDS HUMAN VERIFICATION` с перечнем вопросов.
- В конце: какие файлы отданы, что проверено, что не проверено, что требует решения.
