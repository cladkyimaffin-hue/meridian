## Идея пользователя (2026-11-22, обсуждение)
Конструктор отчётов «пазл»: показывать таблицы базы со столбцами; пользователь набрасывает на поле имена столбцов
из разных таблиц и собирает отчёт; бэкенд строит запрос и показывает таблицу; отчёт можно сохранить в новый или
существующий раздел.

## Факты для оценки (VERIFIED 2026-11-22)
* `LV_MERIDIAN`: 1238 таблиц, 1306 представлений, 12134 столбца, 2076 объявленных внешних ключей (связи частично можно получать автоматически).
* `MRDN_Exchange`: 31 таблица, внешних ключей нет, связи с `LV_MERIDIAN` задаются вручную (сравнение кодов с `COLLATE DATABASE_DEFAULT`).
* `constructor_ro` не может создавать представления и таблицы (право CREATE VIEW/TABLE: нет).

## Риски свободной сборки (INFERRED)
* Неверные соединения дают тихо неверные цифры (размножение строк, двойные строки движения, языковые справочники).
* Суммирование между единицами измерения; чувствительные столбцы (пароли, КМ, персональные данные).
* Нужны понятные подписи столбцов (в БД имена технические) и ограничения на размер выборки.

## Возможные этапы
1. «Витрины»: 3–5 описанных вручную наборов данных (остатки, приходы, задачи, движения) с понятными полями, типами и пометками «чувствительное/нельзя суммировать».
2. Сборка отчёта из полей одной витрины: выбор столбцов, фильтры, сортировка, группировка и итоги; SQL строит бэкенд из белого списка.
3. Сохранение отчётов (хранилище вне git) в разделы; вопрос владельцев и прав.
4. Свободное соединение таблиц по графу связей (внешние ключи) с проверкой пути.
Альтернатива/дополнение: Metabase поверх `constructor_ro` для разовых исследований (запросы в своей базе, без git).

не было флага `emit_filter`, из-за чего клик ничего не делал. Проверено в браузере, фильтр
