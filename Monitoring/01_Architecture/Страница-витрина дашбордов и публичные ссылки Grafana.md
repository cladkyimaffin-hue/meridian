# Страница-витрина дашбордов и публичные ссылки Grafana

## Что настраивается и зачем

На `wmssql-analytics` (192.168.12.202) работает статическая страница-витрина со ссылками на дашборды Grafana. Для каждого дашборда на странице карточка: название, аннотация, картинка основных полей и кнопка «Открыть дашборд (только чтение)». Кнопка ведёт на публичный дашборд Grafana: он открывается без входа и не редактируется. Задача из решения администратора 2026-11-12 (веб-страница со ссылками на готовые дашборды); макет и параметры согласованы 2026-11-15.

## Предварительные условия
- [x] Решения администратора 2026-11-15 (таблица ниже).
- [x] Условия проверены 2026-11-15, только чтение: порты 80 и 443 свободны, ОЗУ доступно около 2,8 ГБ, диск 69 ГБ свободно, на сервере уже есть образ Caddy.
- [x] Grafana 12.2.0 с функцией публичных дашбордов («Share externally») доступна; на дашбордах, подключённых из файлов, она работает.

## Решения администратора (2026-11-15)

| Вопрос | Решение |
|---|---|
| Вход на страницу | без пароля; решение «пока», вернуться до того, как страница станет доступна из других сетей |
| Откуда открывают | подсети 192.168.12.x и 192.168.0.x |
| Картинки основных полей | пока ручные снимки экрана от администратора (сейчас вместо них примеры SVG) |
| Группировка | по серверам, макет A: колонка на сервер, карточки сеткой; вернуться к выбору, когда серверов больше шести или дашбордов больше десяти |
| Адрес | `http://192.168.12.202`, порт 80, простой HTTP, DNS-имя не вводить |
| Доступ к Grafana только на чтение | публичные дашборды Grafana («Share externally», «Anyone with the link»); анонимный Viewer не берётся |
| Первая версия | все карточки, состав и порядок меняются при появлении серверов или смене приоритета |
| Каталог и веб-сервер | `/opt/portal`, Caddy отдельным контейнером |
| Шаги 5, 6 и 7 плана (сузить `ufw`, положить настоящие снимки, документы) | пропущены 2026-11-15; шаг 7 (документы) выполняется этим документом |

## Как устроена страница

- Каталог `/opt/portal` (владелец — рабочая учётная запись): `docker-compose.yml`, `Caddyfile` (раздача статики на порту 80, автоматический HTTPS выключен), `index.template.html` (шаблон), `build.py` (сборщик), `links.json` (карточки и токены, права 600), `make_example_svg.py` (рисует пример картинки по текущим значениям), `site/index.html` (результат сборки), `site/img/` (картинки).
- Контейнер `portal-caddy`: образ `caddy:2`, порт 80, лимит ОЗУ 128 МБ, `restart: unless-stopped`, сеть `portal_default`; фактически около 11 МБ ОЗУ. Каталог `site/` смонтирован напрямую, перезапуск контейнера после пересборки не нужен.
- Данные карточек (название, аннотация, картинка, ссылка, подпись) лежат в `links.json` отдельно от оформления: смена порядка, состава или макета не требует переделки дашбордов. Токены только в `links.json`; шаблон и скрипты токенов не содержат и могут храниться в публичном репозитории.
- `build.py` собирает `site/index.html` из шаблона и `links.json`. Картинка карточки берётся из `site/img/<ключ>.<расширение>`; поддерживаются PNG, JPG, WEBP и SVG (порядок: PNG первым). Подпись под картинкой: поле `shot_note` в `links.json` или дата файла («Скриншот от …»).
- Ссылки «Открыть дашборд»: `http://192.168.12.202:3000/public-dashboards/<токен>` с параметрами диапазона 12 часов и обновления раз в минуту (допущение, меняется в `links.json`).
- Картинки на 2026-11-16: рисунки SVG в стиле Grafana, нарисованные скриптом по реальным значениям с публичных ссылок, с честной подписью «Пример: рисунок по реальным значениям на ДД.ММ.ГГГГ, не снимок экрана». Оформление и значения могут отличаться от настоящего дашборда.

## Публичные ссылки Grafana

1. На дашборде: Share, Share externally, Anyone with the link. Ссылка вида `/public-dashboards/<токен>`. Выполняет администратор в интерфейсе Grafana (класс [W]; откат: отключить ссылку тем же окном).
2. Проверено 2026-11-15 по API с самого сервера, без входа: адрес отвечает HTTP 200 и отдаёт дашборд, `canEdit` и `canSave` равны false.
3. Настройка публичной ссылки хранится в базе Grafana (том `monitoring_grafana-data`, с записью); файлы дашбордов подключены только для чтения. По сохранившейся записи ссылки переживают перезапуск контейнера (INFERRED, перезапуск не проверялся).
4. Токены. Каждая ссылка содержит случайный токен. Значения лежат только в `/opt/portal/links.json` (права 600) и в его резервных копиях `links.json.bak*` (в копиях тоже токены), а также в сырых чатах приватного `meridian-secrets`. В публичный репозиторий токены не идут. Место внесено в приватный реестр секретов (значений там нет).
5. Токен можно перевыпустить или отозвать в окне «Share externally»; после этого обновить `links.json` и пересобрать страницу.

## Правка двух дашбордов под публичные ссылки

Причина (VERIFIED, 2026-11-15): публичные дашборды не подставляют значения переменных в запросы. На «Node Exporter Full» источник данных был переменной `ds_prometheus`: 88 запросов получили HTTP 500, в логе Grafana «data source not found» с подставленным именем `public-ds`. На «ТЕСТ» запросы зависели от переменной `host`: проходили, но возвращали пустой результат. У «wmsDB: Сервер» переменных нет, и он работал сразу.

Что изменено [W] (файлы в `/opt/monitoring/grafana/dashboards/`, копии до правки `*.bak-20261115`):

| Дашборд | Файл | Правка |
|---|---|---|
| ТЕСТ (wmsDB-TEST) | `windows-mssql.json` | везде `$host` заменено на `wmsDB-TEST` (45 мест), переменная `host` убрана |
| Node Exporter Full | `node-exporter-full.json` (около 470 КБ) | источник данных, `$job` и `$node` заменены значениями (`prometheus`, `node_linux`, `host.docker.internal:9100`), четыре переменные убраны |

Цена правки: в «ТЕСТ» больше нет выбора хоста (показывает только `wmsDB-TEST`, для `wmsDB` есть отдельный дашборд); «Node Exporter Full» показывает только `wmssql-analytics`, при появлении других Linux-серверов понадобится отдельный дашборд на каждый или возврат к вопросу.

Результат проверки по публичным ссылкам, запрос к каждой панели (VERIFIED, 2026-11-15):

| Дашборд | Панелей с запросами | С данными | Пусто | Ошибки |
|---|---|---|---|---|
| wmsDB: Сервер | 29 | 29 | 0 | 0 |
| ТЕСТ (wmsDB-TEST) | 28 | 28 | 0 | 0 |
| Node Exporter Full | 124 | 108 | 16 | 0 |

16 пустых панелей «Node Exporter Full» (Systemd, температура и вентиляторы, ECC, TCP Stat, PIDs и другие) по названиям опциональные: экспортер здесь, по-видимому, этих метрик не отдаёт (INFERRED, по сборщикам не проверялось). Это не ошибка ссылки, но зритель увидит «Нет данных». В логе Grafana ошибок provisioning после правки нет. Обычный вход в Grafana под администратором после правки не проверялся.

## Эксплуатация и откат

Пересборка страницы после правки `links.json` или картинок [W]:

```bash
cd /opt/portal && cp -p links.json links.json.bak-<ГГГГММДД>
cd /opt/portal && python3 build.py
```

Пример картинки для карточки по текущим значениям с публичной ссылки [W]:

```bash
cd /opt/portal && python3 make_example_svg.py <ключ_карточки>
```

Настоящий снимок: положить файл как `site/img/<ключ_карточки>.png`, удалить одноимённый `.svg` (приоритет у PNG), выполнить `python3 build.py`.

Откат страницы [W]: остановить контейнер и при полном удалении убрать каталог (удаление только по подтверждению администратора [D]).

```bash
cd /opt/portal && docker compose down
```

Дословное содержимое `docker-compose.yml`, `Caddyfile`, `index.template.html` и `build.py` в материалах не сохранилось (файлы создавались на сервере); при необходимости читать с `wmssql-analytics`.

## Решения и риски
- Простой HTTP без TLS: трафик идёт открытым текстом; решение администратора для локальной сети.
- Ссылки без пароля и анонимный просмотр: любой, у кого есть ссылка и доступ к адресу в сети, видит дашборд. Администратор принял вход без пароля «пока»; вернуться до доступа из других сетей.
- `ufw` разрешает порты 80 и 3000 «из любого места», сужение до подсетей 192.168.12.x и 192.168.0.x отложено (OPEN).
- Маршрут из 192.168.0.x до `wmssql-analytics` не проверялся (UNKNOWN); пользователям из этой подсети нужен доступ и к порту 3000.
- Токены ссылок лежат в `links.json` и его копиях; кто может прочитать каталог `/opt/portal`, видит все ссылки (права 600 у `links.json`).
- Пороги и вид дашбордов в браузере администратором в этом документе не подтверждались; замечаний по картинкам не получено.
- Единая точка отказа: страница, Grafana, Prometheus и сервер паролей на одной ВМ.
