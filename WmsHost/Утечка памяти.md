**Шаг 1.3 — Анализ процесса ppbd.exe и его связи с Hyper-V**

Процесс `ppbd` потребляет **44 474 секунды CPU** (что эквивалентно ~12 часам непрерывной загрузки одного ядра) и занимает **~396 МБ RAM**. ### Действие:
Выполните следующую команду в PowerShell (от имени администратора), чтобы определить, какой именно процесс скрывается за именем `ppbd`, и проверить его родительский процесс:

```powershell
Get-CimInstance Win32_Process -Filter "Name='ppbd.exe'" | Select-Object Name, ProcessId, ParentProcessId, CommandLine, Path | Format-List
```

Также проверьте, не является ли это дочерним процессом `vmwp.exe` (Hyper-V Worker Process):

```powershell
$ppbd = Get-Process -Name ppbd -ErrorAction SilentlyContinue
if ($ppbd) {
    $parent = Get-CimInstance Win32_Process -Filter "ProcessId=$($ppbd.Id)" | Select-Object -ExpandProperty ParentProcessId
    Write-Host "PID ppbd: $($ppbd.Id)"
    Write-Host "Parent PID: $parent"
    if ($parent) {
        $parentProc = Get-Process -Id $parent -ErrorAction SilentlyContinue
        Write-Host "Parent Process: $($parentProc.Name) (PID: $parent)"
    }
} else {
    Write-Host "Процесс ppbd не найден"
}
```

**Шаг 1.7 — Перезапуск службы через Stop/Start по имени из WMI**

Ошибка `Сбой при сравнении двух элементов массива` возникает, потому что `Restart-Service -InputObject` некорректно обрабатывает объекты WMI (`Win32_Service`). Для надёжного перезапуска необходимо использовать методы самого объекта WMI (`StopService` и `StartService`) или найти службу через стандартный cmdlet `Get-Service`, используя имя, полученное из WMI.

Выполните этот полный блок кода в PowerShell (от имени администратора). Он сначала получает корректное системное имя службы, затем останавливает её, ждёт завершения и запускает заново:

```powershell
# 1. Получаем системное имя службы
$svcWmi = Get-WmiObject Win32_Service | Where-Object { $_.PathName -like "*ppbd.exe*" }

if (-not $svcWmi) {
    Write-Host "ОШИБКА: Служба ppbd.exe не найдена" -ForegroundColor Red
    return
}

$serviceName = $svcWmi.Name
Write-Host "Найдена служба: '$serviceName' (PID: $($svcWmi.ProcessId))" -ForegroundColor Green

# 2. Останавливаем службу
Write-Host "Остановка службы..." -ForegroundColor Yellow
Stop-Service -Name $serviceName -Force -Verbose
Start-Sleep -Seconds 3

# 3. Проверяем остановку
$proc = Get-Process -Name ppbd -ErrorAction SilentlyContinue
if ($proc) {
    Write-Host "Принудительное завершение процесса PID $($proc.Id)" -ForegroundColor Yellow
    Stop-Process -Id $proc.Id -Force
    Start-Sleep -Seconds 2
}

# 4. Запускаем службу заново
Write-Host "Запуск службы..." -ForegroundColor Yellow
Start-Service -Name $serviceName -Verbose
Start-Sleep -Seconds 5

# 5. Финальная проверка
$newProc = Get-Process -Name ppbd -ErrorAction SilentlyContinue
if ($newProc) {
    Write-Host "УСПЕХ: Служба запущена с новым PID: $($newProc.Id), RAM: $($newProc.WorkingSet / 1MB) MB" -ForegroundColor Green
} else {
    Write-Host "ВНИМАНИЕ: Процесс ppbd.exe не найден после запуска" -ForegroundColor Red
}
```

### Протокол (обновлённый):
- Прямой `Restart-Service -InputObject` для WMI-объекта вызывает ошибку сравнения массивов.
- Имя исполняемого файла (`ppbd.exe`) ≠ имя службы (`PowerPanel Business Service`).
- Требуется двухэтапный подход: получение имени → `Stop-Service` → `Start-Service`.
- Добавлена принудительная остановка процесса на случай, если служба «зависла» и не реагирует на `Stop-Service`.

**Шаг 1.29 — Оценка рисков изменения параметров памяти для wmsDB**

Изменение конфигурации памяти (особенно переключение с Static на Dynamic Memory) для работающей базы данных несет следующие риски:

1.  **Повреждение транзакций БД:** Если ВМ не выключится корректно (`Stop-VM -ShutDown`), а будет принудительно остановлена (`-TurnOff`) из-за зависания, незафиксированные транзакции в SQL Server могут быть потеряны или повреждены журналы транзакций (LDF).
    *   *Митигация:* Перед остановкой выполнить `CHECKPOINT` внутри SQL Server и убедиться, что все активные транзакции завершены.
2.  **Невозможность запуска после изменений:** Если новый лимит Minimum RAM (например, 16 ГБ) окажется больше, чем физически доступно на хосте в момент старта, ВМ не включится.
    *   *Митигация:* Убедиться, что на хосте есть запас >20 ГБ перед стартом.
3.  **Деградация производительности после включения DM:** При первом запуске с Dynamic Memory SQL Server может агрессивно забрать весь доступный объем до Maximum, вызвав временную нагрузку на диск при сбросе старого кэша.
    *   *Митигация:* Настроить `Max Server Memory` внутри SQL Server *до* включения DM, чтобы он не пытался занять всё доступное пространство сразу.
4.  **Потеря конфигурации Hyper-V:** В редких случаях при редактировании `.vmcx` файла работающей Gen2 VM может повредиться файл конфигурации.
    *   *Митигация:* Сделать копию папки `D:\VMs\wmsDB` (или где лежат конфиги) перед изменениями.
