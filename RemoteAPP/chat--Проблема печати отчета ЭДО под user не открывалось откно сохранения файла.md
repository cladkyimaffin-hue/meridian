## Почему не работает под user (даже в группе администраторов):

### 1. **Ограничения UAC (User Account Control)**
Даже если вы добавили `user` в группу администраторов, в Windows Server 2022 действует **UAC Remote Restrictions**. При подключении через RDP токен администратора фильтруется, и пользователь получает ограниченные права.

**Решение** - на сервере в реестре:
```
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System
LocalAccountTokenFilterPolicy = 1 (DWORD)
```

### 2. **Права NTFS на папку сохранения**
Из документации (Шаг 17): программа Lvision пытается сохранить отчет в папку, но у `user` нет прав:

**Проверьте:**
- Права на папку `C:\Users\user\Documents` (или где сохраняется отчет)
- Права на `%TEMP%` пользователя
- Права на папку программы `C:\LVision` (если там пишутся временные файлы)

**Решение:**

**Шаг 1.3 — Отключение фильтрации токенов UAC для локальных учетных записей (Remote UAC)**

**Объяснение / действие:**  
Результаты ваших проверок точно подтверждают гипотезу.  
1. Файл создается и удаляется → NTFS-права на папку в порядке.  
2. `whoami` выдает пустую строку → токен пользователя `user` имеет **средний уровень целостности** (Medium Integrity).  

В рабочей группе (Workgroup) Windows Server по умолчанию применяет строгую фильтрацию UAC к *любой* учетной записи при удаленном подключении (RDP/RemoteApp), **кроме встроенной учетной записи `Администратор`**. Даже если `user` добавлен в группу "Администраторы", его токен урезается. Когда программа Lvision пытается вызвать системный диалог сохранения (особенно если он взаимодействует с перенаправленными дисками клиента `\\tsclient\...` или требует повышенных привилегий для COM-объектов), операция тихо завершается ошибкой доступа, и окно просто не появляется.

Чтобы это исправить, необходимо явно разрешить локальным учетным записям получать полный (нефильтрованный) токен при удаленном подключении. Это делается через параметр реестра `LocalAccountTokenFilterPolicy`.

**Команда для выполнения на сервере (PowerShell от имени Администратора):**
```powershell
New-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" -Name "LocalAccountTokenFilterPolicy" -Value 1 -PropertyType DWord -Force
```

**Важно:** Для вступления этой политики в силу **требуется полная перезагрузка сервера** (или как минимум полный выход из системы (Sign out) для пользователя `user` и перезапуск службы `TermService`, но перезагрузка надежнее, так как генерация токенов происходит на уровне LSASS при старте системы).

**Сверка с environment_facts:**  
- Среда: Рабочая группа (Workgroup).  
- Пользователь: `user` (не встроенный администратор).  
- Симптом: Работает только под встроенным администратором.  

**Как проверить результат:**  
1. После перезагрузки подключитесь под `user` через RemoteApp.

3. Теперь должна появиться строка, содержащая `Высокий обязательный уровень` (High Mandatory Level).  
4. Попробуйте сформировать и сохранить отчет ЭДО.
