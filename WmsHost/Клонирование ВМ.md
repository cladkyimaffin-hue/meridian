### Шаг 1.3 — Создание копии виртуального диска

Самый надежный способ создать дубликат в Hyper-V без использования мастера экспорта/импорта (который иногда ведет себя капризно с путями) — это физически скопировать файл диска и затем создать новую ВМ, указав ей этот новый файл.

**Действие:**

Нам нужно скопировать файл `wmsWiFi.vhdx` в новую папку (или в ту же, но с новым именем). Рекомендуется создать отдельную папку для новой ВМ, чтобы не запутаться в файлах.

Давай назовем новую машину, например, `wmsWiFi-Copy` (или придумайте свое имя, если есть нейминг-конвенция). Для примера будем использовать `wmsWiFi-Copy`.

Выполните в PowerShell (от имени Администратора) на хосте следующую команду. Она создаст структуру папок и скопирует диск.

*Внимание: Копирование может занять время в зависимости от размера диска (у вас выделено до 6 ГБ RAM, но размер самого диска может быть больше) и скорости дисковой подсистемы.*

```powershell
# 1. Создаем переменные для удобства
$SourceDisk = "D:\VMs\wmsWiFi\Virtual Hard Disks\wmsWiFi.vhdx"
$DestDir = "D:\VMs\wmsWiFi-Copy\Virtual Hard Disks"
$DestDisk = "$DestDir\wmsWiFi-Copy.vhdx"

# 2. Создаем папку для новой ВМ (если её нет)
New-Item -ItemType Directory -Force -Path $DestDir

# 3. Копируем файл диска
# Используем Copy-Item. Это может занять несколько минут.
Copy-Item -Path $SourceDisk -Destination $DestDisk -Verbose
```

**Что делает эта команда:**
1.  Создает папку `D:\VMs\wmsWiFi-Copy\Virtual Hard Disks`.
2.  Копирует содержимое `wmsWiFi.vhdx` в новый файл `wmsWiFi-Copy.vhdx`.

**Протокол (зафиксировано):**
*   **Исходный диск:** `D:\VMs\wmsWiFi\Virtual Hard Disks\wmsWiFi.vhdx`
*   **Статус ВМ:** Выключена (предположительно, согласно Шагу 1.2).
*   **Целевой путь для копии:** `D:\VMs\wmsWiFi-Copy\Virtual Hard Disks\wmsWiFi-Copy.vhdx`
*   **Метод:** Прямое файловое копирование (bit-by-bit copy через ОС).

2.  Дождитесь завершения копирования (появится новая строка приглашения ввода).

В отличие от физических компьютеров, где есть отдельный BIOS/UEFI чип и отдельный жесткий диск, в Hyper-V вся "начинка" компьютера (загрузчик GRUB, ядро Linux, файловая система Ubuntu, все программы и настройки WiFi) упакована в этот один файл-контейнер `.vhdx`.

**Пояснение:**
1.  **Файл `.vhdx`** = Это полный клон физического жесткого диска (HDD/SSD). Внутри него лежит всё: от загрузочного сектора до последнего конфигурационного файла.
2.  **Конфигурация ВМ** (папка `D:\VMs\wmsWiFi`) = Это просто настройки "железа" (сколько дать памяти, сколько ядер, какой MAC-адрес у сетевой карты). Эти настройки мы создадим заново на следующем этапе через PowerShell, указав им использовать *новый* скопированный файл диска.

Поэтому, когда мы копируем `wmsWiFi.vhdx` в `wmsWiFi-Copy.vhdx`, мы делаем полную побитовую копию всей системы. Ничего больше копировать не нужно для переноса самой ОС и данных.

### Шаг 1.12 — Отключение Secure Boot

Для запуска Linux-систем, перенесенных таким образом, или просто для избежания конфликтов подписей, стандартная практика в Hyper-V — отключить Secure Boot для этой ВМ (или сменить шаблон на "Microsoft UEFI Certificate Authority", но отключение надежнее и быстрее для восстановления работоспособности).

**Действие:**
Нам нужно выключить машину (она сейчас в ошибке) и изменить настройку прошивки.

Выполните команды в PowerShell:

```powershell
# 1. Останавливаем ВМ (если она зависла на экране ошибки)
Stop-VM -Name "wmsSQL-Analytics" -TurnOff

# 2. Отключаем Secure Boot
Set-VMFirmware -VMName "wmsSQL-Analytics" -EnableSecureBoot Off

# 3. Проверяем, что настройка применилась
Get-VMFirmware -VMName "wmsSQL-Analytics" | Select-Object VMName, SecureBoot
```

# ИНСТРУКЦИЯ: Клонирование и перепрофилирование Ubuntu VM в Hyper-V

**Цель:** Создать полную копию существующей виртуальной машины Ubuntu, изменить её роль, IP-адрес и имя хоста.
**Среда:** Windows Server / Windows 10/11 с ролью Hyper-V.
**Метод:** "Холодное" клонирование (через копирование VHDX) + ручная настройка ОС.

---

## ЭТАП 1: Подготовка исходной машины

### Шаг 1.1 — Корректное выключение ВМ
Чтобы избежать повреждения файловой системы Linux (ext4), машину нужно выключать штатно, а не "сбрасывать питание".

1.  Откройте **Hyper-V Manager**.
2.  Найдите исходную ВМ (например, `wmsWiFi`).
3.  Нажмите **Выключить (Shut Down)**. Дождитесь статуса "Выключена".
    *   *Альтернатива (PowerShell):* `Stop-VM -Name "SourceVMName"`

### Шаг 1.2 — Определение путей к файлам
Нам нужно знать, где физически лежит диск.
Выполните в PowerShell:
```powershell
Get-VMHardDiskDrive -VMName "SourceVMName" | Select-Object Path
```
*Запишите путь, например: `D:\VMs\SourceVM\Virtual Hard Disks\SourceDisk.vhdx`.*

---

## ЭТАП 2: Работа с дисками (Файловая система)

### Шаг 2.1 — Создание копии диска
Мы не будем использовать функцию "Экспорт", так как прямое копирование надежнее для смены ролей.

1.  Создайте папку для новой ВМ (если нужно), например `D:\VMs\NewRoleVM\Virtual Hard Disks`.
2.  Скопируйте файл `.vhdx` в новую папку с новым именем.
    *   *PowerShell:*
        ```powershell
        Copy-Item -Path "D:\VMs\SourceVM\...\SourceDisk.vhdx" -Destination "D:\VMs\NewRoleVM\...\NewDisk.vhdx"
        ```
    *   *Важно:* Дождитесь полного завершения копирования. Размер файлов должен совпадать.

---

## ЭТАП 3: Создание новой Виртуальной Машины

### Шаг 3.1 — Определение сетевого коммутатора
Узнайте, к какому свитчу была подключена старая машина, чтобы новая попала в ту же сеть.
```powershell
Get-VMNetworkAdapter -VMName "SourceVMName" | Select-Object SwitchName
```

### Шаг 3.2 — Создание ВМ через PowerShell
Этот метод точнее, чем мастер создания, так как позволяет сразу указать существующий диск.

Замените параметры в скрипте на свои:
```powershell
$VMName = "NewVM-Name"
$Switch = "NameOfYourVirtualSwitch"
$DiskPath = "D:\VMs\NewRoleVM\Virtual Hard Disks\NewDisk.vhdx"
$ConfigPath = "D:\VMs\NewRoleVM" # Где хранить файлы конфигурации

New-VM -Name $VMName `
       -Generation 2 `
       -MemoryStartupBytes 4GB `
       -SwitchName $Switch `
       -VHDPath $DiskPath `
       -Path $ConfigPath

# Настройка ресурсов (пример: 2 ядра, динамическая память 2-6 ГБ)
Set-VMProcessor -VMName $VMName -Count 2
Set-VMMemory -VMName $VMName -DynamicMemoryEnabled $true -MinimumBytes 2GB -MaximumBytes 6GB
```

## ЭТАП 4: Решение проблем загрузки (Critical Step)

### Шаг 4.1 — Отключение Secure Boot
**Внимание:** При клонировании Ubuntu на Hyper-V Generation 2 часто возникает ошибка `The signed image's hash is not allowed (DB)`. Это происходит из-за конфликта подписей UEFI.

1.  Убедитесь, что ВМ выключена.
2.  Выполните команду отключения Secure Boot:
    ```powershell
    Set-VMFirmware -VMName "NewVM-Name" -EnableSecureBoot Off
    ```
3.  Запустите ВМ: `Start-VM -Name "NewVM-Name"`.

## ЭТАП 5: Настройка операционной системы (Ubuntu)

Подключитесь к консоли ВМ (через Hyper-V Manager или `vmconnect.exe`).

### Шаг 5.1 — Смена Hostname
Старое имя хоста осталось внутри системы. Меняем его.
1.  Установить новое имя:
    ```bash
    sudo hostnamectl set-hostname new-hostname
    ```
2.  Исправить файл hosts (чтобы избежать ошибок резолвинга):
    ```bash
    sudo nano /etc/hosts
    ```
    *Найдите строку `127.0.1.1 old-hostname` и замените на `127.0.1.1 new-hostname`.*
    *Сохраните: Ctrl+O, Enter, Ctrl+X.*

### Шаг 5.2 — Смена IP-адреса (Netplan)
Ubuntu использует Netplan. Конфигурация обычно лежит в `/etc/netplan/`.

1.  Посмотрите имя интерфейса:
    ```bash
    ip link show
    ```
    *(Обычно это `eth0` или `ens33`)*.

2.  Отредактируйте конфиг (файл может называться `50-cloud-init.yaml` или `01-netcfg.yaml`):
    ```bash
    sudo nano /etc/netplan/50-cloud-init.yaml
    ```

3.  Измените IP-адрес в секции `addresses`:
    ```yaml
    network:
        ethernets:
            eth0:
                addresses:
                    - 192.168.XX.XX/24  # Ваш новый IP
                routes:
                    - to: default
                      via: 192.168.XX.1 # Ваш шлюз
                nameservers:
                    addresses: [8.8.8.8, 1.1.1.1]
    ```
    *Важно: Соблюдайте отступы пробелами, не используйте Tab.*

4.  Примените настройки:
    ```bash
    sudo netplan apply
    ```

### Шаг 5.3 — Финальная проверка
1.  Проверьте IP: `ip addr show`
2.  Проверьте имя: `hostname`
3.  Проверьте доступность сети: `ping 8.8.8.8`

### Шаг 2.1 — Анализ инцидентов и решений

В ходе работы над задачей клонирования ВМ `wmsWiFi` в `wmsSQL-Analytics` были зафиксированы две критические проблемы, которые блокировали выполнение задачи или создавали риск потери данных.

#### Проблема №1: Файловая путаница и риск целостности данных
**Суть проблемы:**
В ходе Шага 1.3 пользователь переименовал исходный файл диска `wmsWiFi.vhdx` в `wmsSQL.vhdx` и переместил его в директорию `D:\VMs\wmsSQL\Virtual Hard Disks\`.
*   **Риск:** Это создало ситуацию, когда имя файла (`wmsSQL`) не соответствовало его содержимому (Ubuntu от WiFi), а также возникла угроза перезаписи оригинального диска реального SQL-сервера, если бы он существовал в этой папке.
*   **Диагностика:** При проверке наличия файла команда `Test-Path` inizialmente вернула ошибку "Файл не найден", что потребовало проведения полной инвентаризации файловой системы (Шаг 1.5) для поиска физического местоположения образа.

**Решение:**
1.  Проведен поиск всех файлов `.vhdx` в директории `D:\VMs`.
2.  Файл был обнаружен по пути `D:\VMs\wmsSQL\Virtual Hard Disks\wmsSQL.vhdx` (размер 81.72 ГБ).
3.  Пользователь визуально верифицировал содержимое файла, подтвердив, что это именно тот образ Ubuntu, который необходим для новой роли, несмотря на несоответствие размера (81 ГБ) типичному размеру WiFi-сервера.
4.  Работа была продолжена с этим файлом как с источником для новой ВМ.

#### Проблема №2: Ошибка загрузки UEFI (Secure Boot Conflict)
**Суть проблемы:**
При первом запуске созданной ВМ `wmsSQL-Analytics` (Generation 2) загрузка операционной системы не произошла. На экране консоли Hyper-V появилось сообщение об ошибке:
`The signed image's hash is not allowed (DB)`
*   **Причина:** Hyper-V Generation 2 по умолчанию включает функцию **Secure Boot** с профилем Microsoft Windows. Загрузчик клонированной Ubuntu (GRUB/Shim) имеет цифровую подпись, которая не прошла проверку в базе доверенных сертификатов (DB) данной виртуальной машины или конфликтует с политикой безопасности хоста при переносе диска.

**Решение:**
1.  Виртуальная машина была остановлена принудительно (`Stop-VM -TurnOff`).
2.  Выполнена команда отключения Secure Boot для конкретной ВМ:
    `Set-VMFirmware -VMName "wmsSQL-Analytics" -EnableSecureBoot Off`
3.  После повторного запуска (`Start-VM`) система успешно загрузилась, так как проверка подписи загрузчика была пропущена.
