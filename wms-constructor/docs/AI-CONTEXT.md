## Правила работы с пользователем (его сохранённые предпочтения)
* Язык общения русский; небольшие шаги; явная уверенность по выводам (VERIFIED/INFERRED/UNKNOWN).
* Ничего «втихую»: каждое изменение называть; перед необратимыми действиями подтверждение.
* В конце ответа: что сделано, что проверено, что не проверено, что требует решения.
* Без выдуманных данных (пароли, IP, ID). Секреты только в непубличных файлах вне репозитория.
* Команды выписывать в файл команд с классификацией [R]/[W]/[D] (`docs/COMMANDS.md`).
* Сырые чаты не удалять: обрабатывать и помещать в репозиторий (`Chats/`), предварительно убрав секреты и личные данные.

## Superset (проба, состояние на 2026-11-25)

* Папка `superset/`, образ `superset-mssql:6.1.0`, порт 8088, администратор `admin`, пароль в `/opt/wms-constructor-secrets/superset.env`.
* Подключение к MSSQL: `LV_MERIDIAN (WMS)` (`db id=1`, логин `constructor_ro`). Второе подключение под `grafana_ro` создавалось и удалено — в системе должно остаться одно.
* **Найденная и устранённая поломка (VERIFIED 2026-11-25).** В метабазе Superset (Postgres `superset-db`) у таблиц прав FAB отсутствовали sequence для `id` — база восстановлена из дампа без них. Из-за этого права `datasource_access` не создавались, и `POST /api/v1/chart/data` отвечал 403 «requires the datasource N …». Лечение: [superset/fix_fab_permissions.sql](../../superset/fix_fab_permissions.sql), затем `docker restart superset`.
* **Вторая поломка (VERIFIED 2026-11-25).** У 12 старых диаграмм пустой `query_context` → «Chart has no query context saved». Лечение: [superset/backfill_query_context.py](../../superset/backfill_query_context.py). После обеих починок все 16 диаграмм отдают данные (проверено `GET /api/v1/chart/{id}/data/`).
* **Витрина остатков:** набор `dm_stock` (id 10) + дашборд «Остатки склада (параллельный отчёт)», slug `wms-stock-parallel`. Строится скриптом [superset/build_stock_dashboard.py](../../superset/build_stock_dashboard.py) (идемпотентен). Проверено 2026-11-25: 399 строк, 58 230 единиц, 14 зон, анонимный просмотр — HTTP 200.
* API Superset: вход только через сессию (`superset/sscli.py`), JWT не даёт прав на списки. Наборы данных — виртуальные, без `ORDER BY` верхнего уровня (в подзапросе SQL Server запрещает). Анонимный просмотр: роль Public, которой выданы права на наборы данных, плюс `DASHBOARD_RBAC` для дашбордов; дашборд должен быть опубликован (`published=true`) и иметь владельца, иначе он не виден в списках. Оформление: CSS дашборда, HTML-баннеры, свои палитры в `superset_config.py` (палитра остатков — `t_ostatki`).
* Ограничение, которое надо помнить: роль Public после починки имеет `datasource_access` на все наборы, то есть аноним может запрашивать данные через API напрямую, не только через дашборд. Решение по ограничению не принято.

## Metabase (пробная установка, 2026-11-23)
* Папка `metabase/`: `docker-compose.yml` (Metabase v0.65.4.x и PostgreSQL 17, контейнеры `metabase` и `metabase-db`), порт 3001 в локальной сети. Секреты: `/opt/wms-constructor-secrets/metabase.env` (вне репозитория).
* Образ Metabase перенесён с сервера wmswifi (рабочая платформа Wi-Fi, не трогать его контейнеры): Docker Hub с wmssql-analytics грузился слишком медленно.
* Первичная настройка (учётная запись администратора, подключение SQL Server под `constructor_ro`) делается пользователем в браузере. Для работы через API нужен API-ключ, который пользователь кладёт в файл секретов; ключ использовать только внутри команд, значение не выводить.
* Ограничения Metabase (по документации): нет соединений между разными базами (обменная база `MRDN_Exchange` доступна только через SQL по полному имени `MRDN_Exchange.dbo.<таблица>` в одном подключении), отчёты хранятся в PostgreSQL, а не в git (нужны резервные копии).
* Построено скриптом `metabase/build_content.py` (карта идентификаторов в `metabase/content_map.json`): корневая коллекция «LV_MERIDIAN: отчёты по складу», 6 тематических коллекций, 14 дашбордов по разделам YAML, общий дашборд «Ключевые показатели склада» (тахометры), «Главная», пробный дашборд заголовков. Параметры в Metabase: период = число «За сколько дней», зона и товар = текстовые фильтры (одно значение).
* Просмотр без пароля: публичные ссылки Metabase (только просмотр). Ссылки хранятся ВНЕ репозитория: `/opt/wms-constructor-secrets/metabase-public-links.txt`.
* Видимы 52 таблицы, 28 чувствительных столбцов помечены «не показывать» (`hide_unused_tables.py`, `mark_sensitive_columns.py`); пометка не запрещает чтение SQL-запросом.
* Ограничения оформления Metabase (Open Source): нет зебры строк и цвета заголовков; решено: баннеры-картинки SVG, тахометры, цветные шкалы в таблицах.
* Подключения к серверам в Claude Desktop называются `wmssql` (бывш. wmssql-analytics) и `wmswifi` (бывш. debian-server-1).
* Известная проблема: на сервере нестабилен DNS (публичные 1.1.1.1 и 8.8.8.8 теряют 5-20% запросов, внутренний 192.168.0.65 стабилен); git/curl по имени иногда падают, нужна повторная попытка.
* Superset — см. раздел [«Superset»](#superset-проба-состояние-на-2026-11-25) выше (состояние, поломки, витрины).
* Цель пробы: проверить, подходит ли Metabase для идеи конструктора-«пазла» на 5 темах (остатки, приходы, задачи, движение, обмен с 1С).
