# Установка сервера паролей Vaultwarden на wmssql-analytics

## Что настраивается и зачем

На `wmssql-analytics` (192.168.12.202, Ubuntu 24.04) в Docker развёрнут сервер паролей Vaultwarden, совместимый с клиентами Bitwarden. Образец — установка в репозитории `korona` (`Proxmox/07_Vaultwarden`: LXC Debian 12, нативная установка, Caddy), здесь вместо этого Docker. Клиент ставится на ПК пользователя, не на сервере. Решение администратора 2026-11-12: устанавливать сразу, к рискам безопасности сервера вернуться позже.

## Предварительные условия
- [x] Решение администратора: сервер паролей на `wmssql-analytics`, сначала сервер, затем клиент на ПК.
- [x] Условия проверены 2026-11-12 (см. файл фактов): порты 80 и 443 свободны, ОЗУ доступно около 2,9 ГБ, диск 69 ГБ свободно, время синхронизировано, `ghcr.io` отвечает быстро.
- [x] Docker CE 29.9.3 и Compose v5.7.0 уже установлены.
- [x] Сетевая шара `/mnt/wmsbackup` смонтирована для резервных копий.

## Шаги установки и настройки

Все команды и классы риска — в `../COMMANDS.md`, блоки 10 и 11. Выполнялось 2026-11-12 и 2026-11-13.

1. **Образы** [W]: Vaultwarden `ghcr.io/dani-garcia/vaultwarden:1.37.5` (выпуск 2026-11-01, закрывает уязвимости средней тяжести; версия 1.37.2 из `korona` существует, но взята последняя), digest `sha256:4fe17f415f90087377d37c755e0ea3cf189dcc6794e49cdd2a9adbb4937d9e1f`; Caddy 2.11.9, зафиксирован по digest `caddy@sha256:9c1b76fb701c1f77383d3124d9f626e38bcf83bc1255ed47475d4f2420701d03`.
2. **Каталог `/opt/vaultwarden`** [W]: `docker-compose.yml`, `Caddyfile`, `vaultwarden.env` (права 600), `secrets/admin_token.txt` (права 600), `data/` (права 700), `caddy-data/`, `caddy-config/`. Для хеша установлен пакет `argon2` (apt).
3. **Настройки Vaultwarden** (в `docker-compose.yml`): `DOMAIN` равен адресу сайта, регистрация отключена, приглашения включены, подсказки к паролю отключены, лимиты памяти 256 МБ (Vaultwarden) и 128 МБ (Caddy). `ADMIN_TOKEN` задан только хешем Argon2id (параметры m=65536, t=3, p=4) в `vaultwarden.env`; сам токен лежит в файле `secrets/admin_token.txt`.
4. **Caddyfile**: сайт `https://192.168.12.202:8443`, `tls internal`, `encode zstd gzip`, `reverse_proxy vaultwarden:80`; в глобальных опциях `admin off` и `default_sni 192.168.12.202` (без неё заход по IP давал TLS-ошибку). Копия до правки: `Caddyfile.bak-20261112`.
5. **Запуск** [W]: `docker compose up -d` в `/opt/vaultwarden`. Порт 8443: правило `ufw` для него уже существовало, фаервол не менялся; порт 443 оставлен под веб-страницу со ссылками на дашборды.
6. **Ротация токена администратора** [W], [D]: хеш прежнего токена был ошибочно выведен в чат, токен и хеш перевыпущены, контейнер Vaultwarden пересоздан; прежние файлы удалены командой `shred` (по подтверждению администратора).
7. **Клиент на ПК пользователя**: корневой сертификат Caddy установлен в доверенные корневые центры (SHA-256 отпечаток `C0:30:92:93:CA:DD:86:53:5E:52:7B:9A:5D:94:EE:A1:91:13:4A:03:38:D4:70:51:3C:28:02:61:10:3F:A3:1E`, срок до 2036-09-20); пользователь приглашается через `/admin` (раздел Users), регистрируется на главной странице; расширение Bitwarden направляется на `https://192.168.12.202:8443`. Токен администратора читается только в собственном SSH-сеансе.
8. **Резервная копия** [W]: скрипт `/opt/vaultwarden/backup.sh` (права 700, владелец root), службы `vaultwarden-backup.service` и `vaultwarden-backup.timer`, запуск ежедневно в 02:00 UTC (со случайной задержкой до 5 минут). Файл `db_passwd_ДД.ММ.ГГГГ.tar.gz` в `/mnt/wmsbackup/vaultwarden/` (шара `//192.168.12.157/Publick`), хранятся 7 самых новых, старые удаляются после успешной новой копии. Содержимое: снимок `db.sqlite3` (API резервного копирования SQLite и проверка `integrity_check`), каталоги `attachments` и `sends`, если есть; `config.json` включается только при отсутствии в нём ключей с `pass`, `token`, `secret`, `key` в имени (на 2026-11-13 не включён); ключ `rsa_key.pem` и каталог `caddy-data` в копию не входят.

## Откат
- Остановить сервис: `docker compose down` в `/opt/vaultwarden` (данные в `data/` сохраняются).
- Отключить копии: `sudo systemctl disable --now vaultwarden-backup.timer`.
- Полное удаление — только по подтверждению администратора [D]; перед этим сделать копию `data/`.

## Решения и риски
- Решение администратора 2026-11-12: поставить сразу, риски `wmssql-analytics` (sudo без пароля, токен Telegram в двух скриптах, открытый порт 8765, вход по SSH паролем, Grafana без TLS) разбирать позже; перечень — в файле фактов.
- Решение администратора 2026-11-13: DNS-имя для сайта пока не вводить (сайт открывается по IP).
- Копии базы лежат на шаре с именем «Publick» без шифрования; кто может читать папку на Synology, неизвестно (UNKNOWN). База зашифрована клиентскими ключами, но содержит проверочный хеш мастер-пароля; рекомендовано ограничить права папки на Synology или шифровать копии (решение за администратором).
- Единая точка отказа: сервер паролей и мониторинг на одной ВМ; политика снимков Hyper-V не известна (UNKNOWN).
